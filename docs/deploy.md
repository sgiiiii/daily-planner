# Публикация: GitHub + Render + Neon

Что получится: публичная HTTPS-ссылка, настоящая PostgreSQL с постоянным
хранением и автоматический деплой при каждом `git push`.

Все три сервиса бесплатны и не требуют банковской карты:

| Сервис | Роль | Бесплатный тариф |
| --- | --- | --- |
| GitHub | код, CI, автодеплой | публичные репозитории бесплатны без ограничений |
| Neon | PostgreSQL | 0.5 ГБ, автосон при простое |
| Render | Python-сервер (WSGI) | 512 МБ, засыпает после 15 минут без запросов |

Единственный компромисс бесплатного Render — холодный старт 30–60 секунд после
простоя. Он лечится пингом из GitHub Actions (шаг 5) либо платным планом
($7/мес). Всё остальное работает как у обычного продукта.

> Тарифы бесплатных сервисов периодически меняются. Если лимит исчез, тот же
> код разворачивается на PythonAnywhere, Fly.io или своём сервере — приложение
> не привязано к Render.

## 0. Что уже лежит в репозитории

* `app_wsgi.py` и `server/wsgi.py` — WSGI-вход (gunicorn, Render, PythonAnywhere);
* `server/db.py` — один слой данных для SQLite и PostgreSQL;
* `render.yaml` — blueprint: сервис, health check, автодеплой, переменные;
* `.github/workflows/ci.yml` — тесты на SQLite и PostgreSQL плюс проверки интерфейса;
* `.github/workflows/keepalive.yml` — пинг, чтобы сервис не засыпал;
* `requirements.txt` — только продакшн-зависимости (gunicorn, psycopg).

## 1. Репозиторий на GitHub

```bash
git init
git add .
git commit -m "Цифровой ежедневник: приложение, тесты, документация"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/daily-planner.git
git push -u origin main
```

Репозиторий может быть приватным: Render подключается к приватным репозиториям,
Actions на бесплатном тарифе дают 2000 минут в месяц (этого хватает с запасом).
Публичный репозиторий проще, если нужна ссылка на код в портфолио.

## 2. База данных Neon

1. Открыть <https://neon.tech>, войти через GitHub.
2. **New Project**: имя `planner`, регион `AWS eu-central-1 (Frankfurt)` —
   тот же, что у Render, чтобы запросы не ходили через океан.
3. На странице проекта открыть **Connection string** и скопировать строку вида:
   `postgresql://neondb_owner:ПАРОЛЬ@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
4. Таблицы создавать не нужно: приложение применит схему само при первом запросе.

## 3. Сервис на Render

1. Открыть <https://render.com>, войти через GitHub, разрешить доступ к репозиторию.
2. **New → Blueprint**, выбрать репозиторий `daily-planner`.
3. Render прочитает `render.yaml`: сервис `daily-planner`, план Free, регион Frankfurt.
4. В поле **DATABASE_URL** вставить строку из Neon и применить.
5. Дождаться первого деплоя (2–4 минуты) и открыть выданный адрес
   `https://daily-planner-xxxx.onrender.com`.
6. Зарегистрировать свой аккаунт. Демо-аккаунт в продакшене выключен
   (`PLANNER_SEED_DEMO=0`), поэтому чужой человек внутрь не попадёт.

Проверка:

```
GET https://ваш-сервис.onrender.com/api/health
→ {"status":"ok","time":"...","backend":"PostgreSQL"}
```

## 4. Автодеплой

В `render.yaml` стоит `autoDeploy: true`. Render подписан на ветку `main`:
каждый пуш запускает сборку и выкатку, ручных действий не нужно.

```bash
# поправили файл
git commit -am "feat: поиск по задачам"
git push
```

Через 1–3 минуты изменение уже на сайте. В панели Render видно историю
деплоев, логи и кнопку отката.

CI (`.github/workflows/ci.yml`) при этом прогоняет тесты на SQLite и
PostgreSQL, а также 40 проверок интерфейса в headless Chrome. Если тест
красный, пуш лучше откатить — деплой Render сам не остановит, но история
деплоев позволяет вернуться на предыдущую версию одной кнопкой.

## 5. Чтобы ссылка открывалась быстро (keep-alive)

Бесплатный Render засыпает после 15 минут без запросов. Чтобы преподаватель
или вы сами не ждали холодный старт:

1. GitHub → **Settings → Secrets and variables → Actions → Variables**.
2. **New repository variable**: `APP_URL` = `https://ваш-сервис.onrender.com`.
3. Готово: `keepalive.yml` каждые 10 минут дергает `/api/health`.

Лимит Render — 750 часов в месяц на сервис, круглосуточная работа одного
сервиса как раз укладывается в него.

## 6. Проверка готового продукта

* `/api/health` отвечает `backend: PostgreSQL`;
* регистрация, вход, создание задачи, перезагрузка — данные на месте;
* тема переключается и сохраняется в аккаунте;
* с телефона открывается публичный URL, мобильная навигация и формы работают;
* в профиле «Данные → Перенести невыполненные задачи сейчас» срабатывает перенос.

## 7. Локальный запуск с PostgreSQL

```powershell
$env:DATABASE_URL = "postgresql://...?sslmode=require"
python -m server.wsgi --port 8000
```

Или тесты против PostgreSQL:

```powershell
$env:PLANNER_TEST_DATABASE_URL = "postgresql://..."
python -m unittest discover -s tests -v
```

`PLANNER_DB_RESET=1` удаляет таблицы при старте — так тесты получают чистую базу.
На рабочей базе этот флаг выставлять нельзя.

## 8. Переменные окружения

| Переменная | Пример | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://...` | включает PostgreSQL; без неё — SQLite |
| `PLANNER_SEED_DEMO` | `0` | создавать ли демо-аккаунт `demo/demo1234` |
| `PLANNER_SCHEDULER` | `1` | фоновый поток переноса задач |
| `PLANNER_COOKIE_SECURE` | `1` | флаг Secure у cookie (нужен на HTTPS) |
| `PLANNER_DB` | `data/planner.db` | путь к файлу SQLite |
| `PLANNER_DB_RESET` | `1` | удалить таблицы при старте (только тесты) |

## 9. Если что-то пошло не так

| Симптом | Что проверить |
| --- | --- |
| 500 на всех запросах | `DATABASE_URL` (пароль, `sslmode=require`), логи Render → Logs |
| `relation "users" does not exist` | схема не применилась: смотрите traceback в логах, проверьте права пользователя БД |
| Не сохраняется вход | на HTTPS должен быть `PLANNER_COOKIE_SECURE=1`, на http — `0` |
| Первый запрос долгий | холодный старт Render, включите keep-alive |
| 429 при входе | сработал лимит 30 попыток в минуту с одного IP, подождите минуту |
| Медленные запросы | регион Neon и Render должны совпадать (Frankfurt) |

## 10. Альтернативы и что дальше

* **PythonAnywhere (free)** — постоянный диск, SQLite без переезда, всегда
  включён, но без автодеплоя: обновление через `git pull` в консоли и кнопку
  Reload. WSGI-вход `app_wsgi.py` уже совместим.
* **Render Postgres** вместо Neon — один кабинет вместо двух, но у бесплатных
  баз Render ограниченный срок жизни; Neon надёжнее для долгого проекта.
* **Свой домен** — Render → Settings → Custom Domain, затем A/CNAME записи у
  регистратора; HTTPS-сертификат Render выпускает сам.
* **Платная версия Render ($7/мес)** убирает сон и увеличивает память — если
  проект станет «боевым».
